# Исследование: как надёжно выявлять Suno по звуку

## Данные и метод
- Suno: 280 треков (Kukedlc, версии v2–v5.5) + 6 samples + 2 SUDO.
- Люди: 564 клипа FMA-medium + 158 треков MTG-Jamendo (до 2020 г.).
- Варианты:
  - кодеки: orig, MP3 320/128, AAC 256/128, Opus 128, Vorbis 160;
  - обработка: speed ±3…25 %, pitch ±1–2 полутона, atempo, мастеринг, эхо, зал (IR), slowed + зал.
- Метрики:
  - AUROC;
  - TPR@1 % FPR и TPR@0.1 % FPR — доля Suno выше порога, при котором ложно срабатывает 1 % / 0.1 % человеческих окон.
- CV по группам треков. Пороги считаются по общему пулу людей.

## Кристалл: гребёнка 200 Гц
- У Suno в спектре есть линии ровно на k·200 Гц: 200 Гц = 48000/240, то есть шаг кадра декодера 5 мс.
- Линии есть во всех версиях Suno и переживают AAC, MP3, Opus и Vorbis.
- 32 из 40 крупнейших положительных весов lofcz стоят на этой сетке (у переобученной LR — 39 из 40; случайно ожидалось бы около 3 %).
  - Готовая модель уже «знает» этот паттерн, просто видит его неявно.
- Дополнительно есть ВЧ-линии 1500k±50 Гц (19.45–22.45 кГц). Кодеки ≤128 кбит/с их убивают, поэтому это только бонус для HQ-потоков.

## Подход 1. Fakeprint: средний спектр 1–8 кГц и LR
| Окно | Вариант | AUROC | TPR@1 % |
|---|---|---|---|
| 10 с | lofcz, orig / кодеки | 0.9996 | 0.993 |
| 5 с | переобученная LR, AAC 128 | 0.9997 | 0.993 |

- Ограничение: смена скорости в r раз сдвигает гребёнку в 200·r Гц.
  - lofcz слепнет: логит падает до −14…−19, что совпадает с живыми пропусками (около −11…−14).
- Warp search (читать спектр в точках r·f и брать максимум логита по сетке r) возвращает ускоренные и замедленные треки и находит точное r. Пример sudo_0:

  | Вариант | Логит до | Логит после | Найденное r |
  |---|---|---|---|
  | +3 % | −18.9 | +3.1 | 1.0305 |
  | −15 % | −14.3 | +2.7 | 0.85 |

- Для широкой сетки (0.8–1.3) нужна warp-aware модель, обученная на людях при случайных r (`warp_model.py`). Её прогон не завершён.

## Подход 2. Когерентная гребёнка (новый, самый сильный)
- Одно длинное БПФ на окно (10 с, разрешение 0.1 Гц, 44.1 кГц).
- Контраст бина = мощность ÷ локальное среднее в линейной шкале по ±5 Гц.
  - Линейная, а не логарифмическая шкала: иначе дыры MP3-энкодера дают ложные «пики».
- У Suno линии на 200k Гц фазо-стабильны, поэтому в длинном БПФ они узкие и высокие.
- Ложные срабатывания у людей давали луп-гребёнки: сэмпл, бит-в-бит повторяющийся каждые 1/T с, даёт линии на всех кратных 1/T.
  - Решение — вычитать «плотность линий»: 99.5 % квантиль контраста по всей полосе 1–15.8 кГц.
  - У Suno линии есть только на сетке (около 0.05 % бинов), у лупа их тысячи.
- Признак: медиана контраста на 200k Гц минус 99.5 % квантиль. Результат:

  | Окно | Вариант | AUROC | TPR@1 % | TPR@0.1 % |
  |---|---|---|---|---|
  | 10 с | orig | 1.000 | 1.00 | 0.96 |
  | 10 с | AAC 128 | 0.999 | 0.99 | 0.91 |
  | 5 с | orig | 0.997 | 0.97 | 0.84 |
  | 5 с | AAC 128 | 0.994 | 0.92 | 0.70 |
  | per-track, 10 с | orig | 1.000 | 1.00 | 0.99 |

- Прежние варианты того же признака давали TPR@1 % 0.55–0.61.

### 2b. Поиск базы при смене скорости
- Скан базы в диапазоне 160–260 Гц (r 0.8–1.3):
  - грубо — по гармоникам 1–8 кГц, 100 кандидатов;
  - точно — по всем гармоникам до 15.8 кГц.
- База 200·r находится в 98–99.7 % окон Suno (10 с) при +3 %, −15 %, +25 % и в 98 % при slowed + зал.
- Исключение по суб-гармоникам (линии в точках base·(k + j/m), m = 2…16) отличает луп-гребёнки.
- Пары соседних окон с совпадающей базой (±0.05 Гц), 10 с, TPR@1 % / TPR@0.1 %:

  | Вариант | TPR@1 % | TPR@0.1 % |
  |---|---|---|
  | orig | 0.90 | 0.64 |
  | −15 % | 0.88 | 0.52 |
  | +25 % | 0.91 | 0.65 |
  | slowed + зал | 0.62 | 0.30 |

- Остаточные ложные срабатывания: устойчивые тональные звуки людей (синт-пэды, дроны) с гармониками на 224–258 Гц.
  - Следующий шаг: профиль контраста по гармоникам (сохраняется в кеше v4) и сверка r с warp-fakeprint.

### Где когерентная гребёнка не работает
- Pitch shift (rubberband) и atempo пересинтезируют фазу и разрушают когерентность.
- Для них остаётся только fakeprint, и то частично.

## Отвергнутые гипотезы
- Модуляция огибающей 50 Гц: это гармоники темпа.
- Боковой канал L−R: ничего не добавляет к mid.
- Широкая полоса 0.5–16 кГц: не лучше 1–8 кГц.
- Кепстральный скан гребёнки: слабый (z 1.5–2.8 против 1.1–1.6).
- Максимум некогерентного скана: раздут множественными сравнениями.
- Исключение ±50/100/150 Гц на фиксированной базе: не убирает луп-гребёнки.

## Рекомендация для приложения
Пункт 1 внедрён: `src/sunocheck/coherent_comb.py`, порог −2.5 дБ, 2 окна по 10 с подряд. Подбор порога и проверки — в `HYPOTHESES.md`.

1. Добавить детектор когерентной гребёнки 200 Гц как второй независимый голос:
   - одно БПФ на каждые 10 с (или 5 с с порогом построже) при частоте захвата;
   - признак — медиана контраста на k·200 Гц (1–15.8 кГц) минус 99.5 % квантиль контраста полосы;
   - порог около −3 дБ (p99.9 людей на 10 с ≈ −2.8);
   - стоимость: одно rfft на 441–480 тыс. точек раз в 10 с.
2. Для ускоренных и замедленных треков:
   - скан базы 160–260 Гц;
   - срабатывание только если два соседних окна согласны по базе;
   - показывать пользователю найденную скорость r = base/200.
3. Fakeprint оставить как основной детектор для коротких окон.
   - Warp search по r требует анализа на 32 кГц: при r > 1 нужны частоты до 10.4 кГц, а модель работает на 16 кГц.

## Незавершённое
- Warp-aware LR fakeprint (`warp_model.py`), слияние fakeprint и гребёнки по согласию r, обучаемая голова по профилю гармоник (`scan_model.py`).
- Нужны записи живых пропусков (Iron West, Odin Rising, Dark Horizons) в нативной частоте, чтобы проверить гипотезу о смене скорости.
