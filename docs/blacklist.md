# Чёрный список авторов

Многие ИИ-авторы — «фабрики»: десятки треков, сделанных одинаково. Часть из них прячет признаки Suno (например, понижает тон на полутон), и по звуку такой трек ловится только через 10–45 с. Чёрный список решает это иначе: автора достаточно поймать один раз, и дальше его треки помечаются с первой секунды.

## Кто попадает в список

Автор (поле «исполнитель» медиасессии Windows) добавляется, когда его трек отмечен как ИИ одним из трёх способов:

| Событие | Где | Источник в журнале |
|---|---|---|
| Кнопка «Это ИИ» | пульт, меню в трее «Текущий трек — ИИ» | `ai_label` |
| Кнопка «Автора — в чёрный список» | пульт, меню в трее | `button` |
| Приложение само скипнуло трек | режим «Скипать», после любого детектора | `skip` |

Простое обнаружение в режиме «Только отмечать» автора **не** добавляет: в список ведёт только ваше решение или совершённый скип.

## Кто убирается из списка

| Событие | Источник в журнале |
|---|---|
| Кнопка «Это человек» на любом треке автора | `human_label` |
| Вкладка «Чёрный список», выбрать строки и нажать «Убрать из списка» | `remove_button` |

## Что делает список

- Трек автора из списка получает статус «Suno» (DETECTED) на первой оценке, примерно через 1 с звука (настройка «Первая оценка через»).
- В режиме «Скипать» трек сразу скипается, в режиме «Только отмечать» показывается уведомление.
- Причина в уведомлении: «Исполнитель в чёрном списке (добавлен: …)».
- Изменения действуют сразу, без перезапуска: и на текущем треке, и на следующих. Например, «Это ИИ» на играющем треке в режиме скипа сразу его скипнет.
- **Защита от устаревших метаданных:** после скипа список не срабатывает, пока медиасессия показывает тот же скипнутый трек. Иначе, если плеер обновит название с задержкой, следующий трек другого автора скипнется по старому имени. Если вы сами вернулись к скипнутому треку, он доиграет, пока не сменится трек. Звуковые детекторы при этом работают как обычно.

## Сравнение имён

- Имена сравниваются без учёта регистра и пробелов по краям: «RavenStormX» и «ravenstormx » — один автор.
- Строка «A, B» (несколько исполнителей) — отдельный автор: трек «A, B» не совпадёт с «A» в списке.
- Трек без медиасессии (неизвестен исполнитель) в список не попадает; в журнал пишется строка с объяснением.

## Где хранится

`data/blacklist.csv` — журнал событий, строки только дописываются:

```
time,artist,action,source,title
2026-10-14T23:35:48,RavenStormX,add,ai_label,Stand When I'm Afraid (ВАЛЬХАЛА)
```

- По каждому автору действует последняя строка: `add` — в списке, `remove` — нет.
- Повторное добавление уже внесённого автора (или удаление отсутствующего) строку не пишет.
- Журнал можно править вручную, приложение перечитывает его при старте.
- Разметка «Это ИИ» / «Это человек» по-прежнему пишется и в `data/labels.csv` для сравнения метрик; чёрный список от неё не зависит.
- В CSV сессии (`data/sessions`) столбец `blacklisted` = 1, если трек помечен из-за списка.

## Риск

Ложный скип (детектор ошибся на человеке) вносит автора в список, и все его треки начинают скипаться. Проверяйте вкладку «Чёрный список»: в каждой строке видно, откуда пришёл автор (`автоскип`, кнопка). Ошибку исправляет «Это человек» или «Убрать из списка».

## Код

- `src/sunocheck/blacklist.py` — журнал и чистые функции свёртки (`blacklist_entries`, `blacklist_row`, `change_blacklist`).
- `src/sunocheck/listener.py` — `is_blacklisted`: решение и защита после скипа; набор приходит в `ListenConfig.blacklist`.
- `src/sunocheck/gui.py` — кнопки, вкладка, пополнение при скипе. `src/sunocheck/cli.py` (`listen`) тоже пополняет список при скипе.
